Opptra · Product Strategy · v0.1 · 31 Jul 2026

The supply-chain agent workspace.

Today an ops person clicks a button and one hard-wired automation runs. Next, any supply-chain user assembles their own agents from a library of connectors — Amazon, Flipkart, Unicommerce, Sheets, WhatsApp, couriers — and lets them run the daily work, with a human approving anything that touches money or a customer.

Not another Zapier. The vertical agent platform for marketplace operations. Dogfood Opptra first, sell it second.
The thesis

Horizontal agents own generic office work. None of them speak supply chain — GRNs, e-way GSTINs, how a Zepto B2B order cancels differently from a Myntra one. That domain knowledge is the moat, and we already have it in code.

Why now, honestly

A real, forming market — and a narrow way in

Agentic commerce is projected at ~$1T of US retail by 2030, 90+ startups are building, and three protocols (Anthropic's MCP, Google's A2A, OpenAI/Stripe's ACP) are settling into the connector standard. The horizontal winners — Zapier Agents, Lindy, Gumloop, n8n — cover 7,000 generic apps and zero supply-chain depth.

The moat is vertical

Marketplace + UC + courier + WhatsApp connectors, and the playbooks that use them, are ours to build and nobody else's priority.

The real cost is access, not code

Amazon SP-API, Flipkart, WhatsApp all need seller accounts, developer registration, ID verification — weeks of paperwork per connector. We sequence around it.

The MVP is narrow & deep

3–4 connectors + 5 killer playbooks that save a real team hours a day, proven on our own floor before we widen. Not "an AGI that fixes everything" on day one.

The surprising part

The platform is already hiding in the repo

A survey of opptra-scm-platform shows the hard parts are built — just not named as a platform. The one genuine gap: there is no LLM anywhere yet, and connectors are hard-wired into job handlers instead of being a discoverable, composable library. That gap is the build. Everything below is refactoring, not rewriting.

Architecture

Five layers — three already standing

5

Workspace UI evolve

Agent builder, connector gallery, run inbox, approvals, schedules, KPI. Grows out of today's SPA.

4

Agent runtime build on the worker

Trigger → LLM planner (tool schemas) → connector tool-calls → approval gate for money/customer actions → run ledger + memory. Extends BullMQ, doesn't replace it.

3

Connector layer — the moat SDK + build

One uniform Connector shape: auth + typed actions + triggers + an LLM tool-manifest. Native: UC, Google, Vinculum (have) · Amazon, Flipkart, WhatsApp, Slack, couriers (build) · long-tail via MCP / Composio / Nango.

2

Credential vault + identity generalize

Per-workspace, per-connector encrypted credentials. Generalize today's Google/UC token stores into one table.

1

Core platform have

Fastify API · BullMQ · Postgres · Redis · RBAC · audit · one GCP VM. Running in production today.

The pivotal new abstraction is the Connector SDK: every connector — ours or third-party — implements { auth, actions[], triggers[], toolManifest() }. An action's input schema is its LLM tool-use schema, so adding a connector automatically gives every agent new abilities with zero runtime changes. Expose our own connectors as MCP servers, too — that makes Opptra callable from Claude and any external agent.

Build-vs-buy rule: hand-build the supply-chain connectors that are our moat. For generic SaaS breadth, wrap an aggregator (Composio ≈ $29/mo for ~1,000 tools to start; Nango if we later want to own the stack) instead of writing 500 connectors by hand.

The product, concretely

Playbooks that save hours — ship these, not "a chat box"

An agent workspace is worthless without killer default agents. Each is a composition of connectors, shipped as a clone-and-tweak template. The builder is the wrapper; the playbooks are the product.

Packing Autopilot

Each morning: pull today's CREATED SOs, draft per-warehouse packing mail with label + appointment, wait for approval, send, then follow up with invoice + e-way in the same thread.

UC · Sheets · Drive · Gmail/WhatsApp · most built

Stock Sync Guardian

Watch marketplace inventory against Unicommerce; when they drift, flag it — or auto-correct with a human approval.

Amazon/Flipkart · UC · Slack

Exception Autopilot

A live feed of stuck SOs, appointment-expiry cancellations, short-GRN, failed e-way — each with a one-click playbook to resolve it.

UC · Waypoint · Slack/WhatsApp

Appointment & Label Chaser

Pull appointment letters and labels from Drive/Amazon by date, attach them, nudge warehouses on WhatsApp.

Drive · Amazon · WhatsApp

Daily Ops Digest

One message each morning: what shipped, what's stuck, what needs a human — on WhatsApp or Slack.

UC · Waypoint · Slack/WhatsApp

Report Puller

Scheduled inventory / batch pulls to Sheets or GCS. The FMCG version already runs in Python — fold it in.

Delivery

Four phases — each leaves a working, dogfooded system

Phase 0
2–3 weeks

Name the platform

Refactor automation-* into the Connector SDK; build the registry + toolManifest(); generalize the vault; add workspace_id (defaulted). First LLM agent loop behind a flag, driving only existing UC/Google actions. Mostly renaming and wiring — low risk, high leverage. No new external access needed.

Phase 1
3–4 weeks

First outside connectors + approvals UI

Slack inbound bot + WhatsApp (start the Meta paperwork day one). Run inbox with approve/reject. Ship Packing Autopilot and Daily Ops Digest on our own floor. Begin Amazon/Flipkart developer registration now — long lead time.

Phase 2
6–8 weeks

Marketplace connectors + Exception Autopilot

Amazon SP-API + Flipkart (as approvals land) + Shiprocket/Delhivery. Ship Stock Sync Guardian and Exception Autopilot. The "wow" moment — agents that reason across systems.

Phase 3
ongoing

Open the workspace (SaaS)

Flip on multi-tenancy, self-serve connector auth, the connector gallery, MCP in and out, aggregators for the long tail. Onboard the first external seller or 3PL beyond Opptra.

Over to you

Decisions that unblock the build

  1. Which LLM & budget posture? Recommend Claude — we already run on it, and it's native to tool-use + MCP. Agent loops multiply per-run cost, so the existing cost discipline applies double.

  2. Amazon or Flipkart first after Slack/WhatsApp? Whichever seller account we control most cleanly — and start that developer registration this week, because it's weeks of lead time regardless of engineering.

  3. How long internal-only before the first external customer? Recommend proving three playbooks on Opptra for ~6–8 weeks first.

  4. Buy or build the long tail? Recommend Composio to start (fast, cheap), keeping the door open to Nango once volume justifies owning the stack.

  5. Expose our connectors as public MCP servers? Recommend yes, eventually — it turns Opptra into something callable from Claude and any agent: a distribution channel, not just a product.
